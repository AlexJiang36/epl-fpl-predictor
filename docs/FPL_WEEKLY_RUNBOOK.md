# FPL Weekly Runner Runbook

## Why this exists

The weekly workflow must not depend on manually discovering run IDs, filenames,
market schemas, frozen squad paths, prediction manifests, or transfer-state paths.

The canonical local entry point is:

```text
backend/ml/pipeline/run_fpl_refresh.py
```

The runner orchestrates existing stage implementations and writes one auditable
candidate package.

## Current v0.1 scope

Implemented:

- previous-GW FINAL evaluation discovery/reuse;
- optional FINAL POST evaluation through `ml.eval.evaluate_gameweek_post`;
- live gameweek/bootstrap/fixture/finished-actual ingest using a private backend process;
- GW2-GW5 early-season player + match + scoreline prediction preview;
- optional prediction publication and post-publish verification;
- automatic market CSV derivation from the prediction artifact;
- automatic previous Model Team squad discovery;
- stateful ROLL vs legal one-transfer optimization;
- target-GW Model Team XI / formation / captain / vice / ordered bench preview;
- Top 10 player predictions for GKP / DEF / MID / FWD;
- one Markdown summary and one JSON run manifest;
- `--resume`, `--dry-run`, stage timing/status, and fail-closed behavior.

Intentionally blocked:

- generic deadline FINAL FREEZE. `--phase freeze` fails closed until the generic
  freeze producer is wired. PRE/auto never freeze silently.
- GW6+ normal-weekly model activation. v0.1 refuses to fall back to legacy
  baseline models. The safe early-season path is GW2-GW5 only.

`--publish-predictions` is intentionally explicit because it permits database
prediction writes through the existing publisher.

## Reuse today's successful artifacts

For a day where FINAL evaluation / prediction / publish / transfer artifacts
already exist, use `--resume`. The runner prefers matching successful artifacts
instead of rebuilding them.

It will still create a new candidate-package summary so the full weekly state is
visible in one place.

## Output package

For GW2, each PRE run writes under:

```text
private-planning/gw-pre/2026_27/gw02/candidate-package/<runner_run>/
```

Expected files:

```text
summary.md
run_manifest.json
current_market.csv
top10_by_position.csv
top10_by_position.json
top10_by_position.md
weekly_lineup_preview.json
weekly_lineup_preview.csv
weekly_lineup_preview.md
```

The matching prediction and transfer run directories remain immutable evidence
at their existing locations; the candidate package references them by lineage
rather than copying or overwriting them.

## What the user should never have to provide again

Normal PRE must not ask for:

```text
prediction run id
prediction CSV path
prediction manifest path
market CSV path
previous frozen Model Team path
transfer-state path
transfer output directory
Top-10 report path
```

Those are discovered or generated by the runner.

## Safety rules

1. `--resume` reuses compatible successful artifacts.
2. PRE/auto never creates FINAL freeze.
3. Publishing requires `--publish-predictions`.
4. Missing required lineage fails loudly.
5. GW6+ does not silently use old `baseline_rollavg_*` defaults.
6. Previous final snapshots are never overwritten.
7. Model Team remains separate from Team Alex.
8. GW2+ starts from previous owned squad state, not a new scratch-built 15.
9. ROLL remains a first-class transfer option.
10. Every candidate package records stage status and source paths.

## Remaining hardening

The next pipeline-specific hardening should be done inside the canonical runner,
not by adding more manual terminal steps:

- wire the generic immutable `--phase freeze --final-freeze` producer;
- persist a formal generic weekly Model Team state for GW3+;
- wire approved normal-weekly GW6+ prediction source;
- make publish/activation pointers fully generic;
- expose the candidate package to `/ops` / frontend.

Until those are implemented, the runner must fail closed rather than inventing
paths or silently selecting legacy model defaults.
